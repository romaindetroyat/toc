# Phase 4 Plan 02: Se connecter avec sa clé d’accès, se déconnecter, ajouter ou retirer une clé, refaire son code de secours

## Phase Goal

**As a** proche de Romain, **I want to** avoir mon compte, retrouver mes amis et lancer une table ou une partie solo depuis l'application installée, **so that** je joue avec eux sans recopier de lien et je suis prévenu quand c'est mon tour ou qu'on m'invite.

(Mapped from the ROADMAP Phase 4 Goal; see 04-01.)

## This Plan's Slice

After this plan the account works on every device: Marie signs in on her computer with the passkey of her phone (the browser shows a QR code), stays signed in for good, signs out of a shared tablet, adds a passkey for her new phone, removes the old one, and makes a new backup code after confirming with her passkey. The server routes and the browser's account client are done here; the « Se connecter » sheet and « Mon compte » screens that use them come in 04-09 and 04-10.

Output: auth/login.ts, auth/passkeys.ts, auth/challenge.ts, the refresh in me.ts, the workerd tests, the client calls.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → login routes | Unauthenticated: anyone can ask for options and send assertions |
| cookie → passkey and code routes | A stolen or ridden cookie must not add a passkey or read a new code without the user's authenticator |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-28 | Spoofing | login verify | high | mitigate | Signature verified by SimpleWebAuthn against the stored COSE key; the userHandle must equal the owner's random handle; challenges signed, expiring after 5 minutes and spent once |
| T-04-29 | Denial of service | login options on the Free plan's 100 000 rows written per day | medium | mitigate | No D1 write before a valid assertion (stateless signed challenge); the spent row is written only for an assertion that verified |
| T-04-30 | Elevation of privilege | backup-code regeneration with a stolen session (research T-04-06) | high | mitigate | Step-up: a fresh assertion of one of the account's passkeys in the same call |
| T-04-31 | Elevation of privilege | lost phone's session (research T-04-06) | high | mitigate | Removing its passkey deletes the sessions created with it (sessions.passkey_id ON DELETE CASCADE); the last passkey cannot be removed |
| T-04-32 | Spoofing | CSRF on cookie writes (research T-04-01) | high | mitigate | csrf.test.ts covers every write route: non-null same Origin and a JSON content type, SameSite=Lax |
| T-04-33 | Repudiation | session lifetime | low | accept | 400-day sliding sessions are Romain's « reste connecté » (ACCT-02); logout and passkey removal end them; family scale |
| T-04-SC | Tampering | npm installs | high | mitigate | No package is added by this plan |
