# Phase 2 Plan 02: Aucune main ne fuit, même après une reconnexion — et le déploiement prêt

## Phase Goal

**As a** proche de Romain, **I want to** jouer la même partie de TOC avec trois autres, chacun sur son appareil, sur une table dont le serveur fait autorité, **so that** on joue ensemble à distance, sans que personne puisse voir la main d'un autre, et qu'une coupure ne fasse jamais perdre la partie.

(Mapped from the ROADMAP Phase 2 Goal; see 02-01.)

## This Plan's Slice

Plan 02-01 builds every frame from viewFor and eventsFor by construction. This plan proves it the way success criterion 2 asks: a property test over hundreds of random games with disconnects and reconnects, the same oracle on every real socket frame of a whole game in workerd, and a check of the frames two real browsers receive. It also readies the embedded deploy build (narrowed Text glob, dry runs of both configs) so plan 02-10 deploys without surprises.

<objective>
Write the leak oracle once (packages/table/src/oracle.ts), run it as a fast-check property over the pure core and over the frames of a whole workerd game and of two browsers, fix any frame it catches, then narrow the embedded Text glob and check both deploy configs with a dry run.

Purpose: SC2 and RULE-19 proven, not only designed; no deploy-time surprise (Pitfalls 1, 8, 9).
Output: the oracle, three leak tests, the narrowed glob, tools/check-bundle.mjs.
</objective>
