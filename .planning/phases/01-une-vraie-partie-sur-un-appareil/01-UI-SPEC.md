### Visual identity (derived from the board artwork)

The identity is the physical game board, not a new brand: light oak with horizontal grain, dark green felt centre, brown wood aide-mémoire panels, hand-lettered black circled numbers, four saturated player colours, a sketched horse in each corner. The app chrome is the **walnut frame** around that board; the board art is never restyled, recoloured or redrawn (CLAUDE.md constraint). Colours below were sampled from the webp files (felt `#005400`, oak ≈ `#D8C6B0`, panel brown `#A46F2A`, blue `#0100D6`, yellow `#FFFF00`, red `#D40100`, green `#019C01`).

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between step chips (7 splitter), icon–text gap, card-fan micro offsets |
| sm | 8px | Compact padding in chips, gap between buttons, hand-zone vertical padding |
| md | 16px | Default screen gutter (left/right), padding in bars and action zone, gap between stacked blocks |
| lg | 24px | Padding inside sheets/dialogs, gap between form rows in Réglages |
| xl | 32px | Gap between sections on launch and end screens |
| 2xl | 48px | Top/bottom breathing room on launch and end screens, primary button height |
| 3xl | 64px | Page-level spacing on large screens (desktop outer margin) |

Exceptions (each is a multiple of 4 and has a reason):

| Value | Where | Reason |
|-------|-------|--------|
| 44px | every touch target (min width and height) | Phase-1 touch rule from STATE.md (zones tactiles 44 px) |
| 48px | primary button height, As/Roi mode buttons | thumb ergonomics |
| 56px | info bar height; pawn-tray chip height | two 28px rows; 44px target + padding |
| 72px / 100px | hand card size (w × h) on compact screens | five cards fit a 320px viewport (see Hand fan) |
| 88px / 124px | hand card size (w × h) on regular screens | same ratio 1 : 1.41 |
| 72px | action zone minimum height (compact) | one prompt line + one 48px button |
| 200px | 7 splitter panel height (compact) | counter + chips + 2 buttons |
| `env(safe-area-inset-*)` | top bar, hand zone | notch and home indicator (PITFALLS 14) |
| Board units | everything drawn inside the SVG scene | The scene uses a `viewBox` of `0 0 2560 2560`; sizes in board units are converted to screen px with `--px = 2560 / boardPx` (1 screen px = `--px` units). Text and badges inside the scene are sized in screen px via `calc(14 * var(--px))`, never in raw units, so they stay ≥ 14px on screen |

Stroke widths (1–4px), the keyboard focus ring (3px amber stroke plus its 2px walnut `outline-offset` gap: both are stroke geometry, exempt from the spacing scale) and corner radii (8, 12, 16) are not spacing.

## Typography

Exactly four sizes and two weights (400 regular, 700 bold) across the whole phase.

| Role | Size | Weight | Line Height | Font | Usage |
|------|------|--------|-------------|------|-------|
| Body | 16px | 400 (700 for buttons) | 1.5 | Nunito | Action-zone prompts, dialog text, helper text, button labels (700) |
| Label | 14px | 400 muted / 700 emphasis | 1.4 | Nunito | Info bar, seat chips, card tags (« Reçue »), toasts, badges on the board, aria-visible captions |
| Heading | 20px | 700 | 1.2 | Nunito | Sheet/dialog titles, « À toi de jouer », 7 panel title, section titles on launch/end screens |
| Display | 28px | 700 | 1.2 | Caveat | « TOC » title, « Victoire ! » / « Défaite », « Reste 7 » counter, deal banner « Donne 2 sur 3 » |

Rules: numbers that change (counters, `n/8`, « Reste n ») use `font-variant-numeric: tabular-nums`. Minimum on-screen text is 14px everywhere, including text rendered inside the board scene. French typography is mandatory in `fr.ts`: U+202F before `;` `!` `?` `»` and after `«`, U+00A0 before `:`, typographic apostrophe `’`. Copy in this document is written with plain spaces and ASCII apostrophes for readability; the catalogue must convert.

Neutrals: text on dark `#FFF8E1` (crème, ≈15:1 on noyer), muted text on dark `#CDB89E` (≈8:1), text on oak/cream `#2B1D12`, aide-mémoire brown `#A46F2A` for borders and decoration only (never behind text: crème on it is 3.8:1). Disabled = 40% opacity, never a different hue. Card faces `#FFFDF6`; red suits `#C0201A`, black suits `#1A1A1A`.

Accent reserved for (and nothing else):
1. Primary action button fill: « Jouer la partie », « Jouer » (move confirmation), « Poser mes cartes », « Passer cette carte », « Rejouer » (text `#2B1D12`, ≈9:1)
2. Halo on pawns that can be played with the selected card (double ring: 4 units walnut inside, 8 units amber outside) and on the selected pawn
3. Outline (3px) and top bar of playable cards in the hand; outline of the selected card
4. « Reçue » tag and outline on the card received from the partner (D-21)
5. Current-turn marker: the turn dot in the info bar and the ring around the active seat's felt slot
6. Keyboard focus ring (3px amber with 2px walnut offset)

Never amber: body text, panel backgrounds, decorative borders, seat identity.

Destructive `#A32018` reserved for: « Abandonner la partie » confirm button, the capture badge disc (× on a pawn that the previewed move would eat). Because red is also a player colour, destructive elements always carry text or a `×` shape and never appear as a plain red blob.

### Player identity colours (data colours, not part of 60/30/10)

Colours are taken from the artwork. Colour is never the only identifier: each seat has a name, a glyph, and a fixed screen position.

| Seat | Board fill | Pawn body | Glyph | Team | Board rotation so this seat is at the bottom |
|------|-----------|-----------|-------|------|------|
| Bleu | `#0100D6` | `#1A22E0` | circle ● | with Rouge | 0° |
| Jaune | `#FFFF00` | `#F5D000` | triangle ▲ | with Vert | −90° (quarter turn counter-clockwise) |
| Rouge | `#D40100` | `#D40100` | square ■ | with Bleu | 180° |
| Vert | `#019C01` | `#019C01` | star ★ | with Jaune | +90° (quarter turn clockwise) |

Pawn shading tokens derive from the body colour: light = mix(body, `#FFFFFF`, 0.35), dark = mix(body, `#2B1D12`, 0.40); outline always `#2B1D12`, 3 board units (yellow on oak is ≈1.2:1, the outline carries the contrast).

**Seat chip pattern** (used in info bar, launch tiles, tapis sheet, end screen): cream pill `#FFF8E1`, 8px horizontal padding, glyph (16px) filled with the seat colour and a 2px `#2B1D12` stroke, name in Label 700 `#2B1D12`. Because text is always walnut on cream, contrast holds for every seat colour including yellow.

Screen position after rotation (derived from D-05): bottom = human, left = the next seat clockwise, top = partner, right = the previous seat. Human Bleu: Jaune left, Rouge top, Vert right. Human Jaune: Rouge left, Vert top, Bleu right. Human Rouge: Vert left, Bleu top, Jaune right. Human Vert: Bleu left, Jaune top, Rouge right. The artwork's aide-mémoire panels and numerals face their own seat, so the bottom player always reads theirs upright; this is intended and must not be "corrected".

### Game screen — responsive rule

Board size `B = min(100vw, 100dvh − chrome, 880px)`; the board is always a square, centred horizontally, never cropped.

| Layout | Condition | Structure |
|--------|-----------|-----------|
| Compact portrait | portrait and width < 600 | Vertical stack: safe-top → info bar 56 → board `B` → action zone (min 72, grows to absorb leftover height up to 160, content vertically centred) → hand zone 132 + safe-bottom. Chrome = 56 + 72 + 132 = 260 |
| Wide portrait | portrait and width ≥ 600 | Same stack, board max 880, content column max 880 centred, regular card size |
| Landscape | landscape (phones included) | Two columns with 16px gap: board `B = min(100dvh − 32, 100vw − 320 − 48)` at left; right panel ≥ 320 (max 400): info bar (56) → action zone → hand zone, hand anchored to the bottom of the panel. Outer margin 16 (64 at ≥ 1280px width) |

Minimum supported viewport: 320 × 480 portrait, 480 × 320 landscape. Board `viewBox` is `0 0 2560 2560`, scene is one SVG. Safe-area insets and `viewport-fit=cover` are applied; `touch-action: manipulation` and `overscroll-behavior: none` on the game screen; `user-select: none` on board and cards.

Board assembly in board units: quarters at Jaune (0,0), Rouge (1280,0), Bleu (0,1280), Vert (1280,1280). The felt square is x/y 853..1707 (854 units, 33.4% of the side). The whole scene (art + cell geometry + felt slots) is rotated as one group by the rotation of the human's colour (table above). Pawns, cards, badges and halos are **not** rotated: only their anchor positions are transformed, so they always stay upright on screen.

Board delivery (PITFALLS 19): a build-time composite of the four quarters at 1280 and 2560 px wide (`srcset`), source quarters stay in `assets/plateau/`. While loading, show oak colour `#D8C6B0` with the felt square in `#005400` (no spinner) and fade the image in over 200ms (instant under reduced motion). Cell coordinates come from one calibrated normalised file (`layout.json`, 0..1); a `?debug=geometry` overlay draws the 72 indices, stables, homes, and the felt slots for visual review.

### 7 splitter panel (D-17, PLAY-03)

Replaces the action zone **and the hand fan** (the played 7 is shown as a mini card chip inside the panel) so it fits a 667px-high phone: bar 56 + board 375 + panel 200 = 631. Layout, top to bottom: title (Heading) + « Reste {n} » counter (Display, right-aligned); plan list (one row per micro-move, Label); step chips row (7 chips 44 × 44, 4px gap = 332px, fits 358); buttons row (« Retirer le dernier pas » undo, « Tout annuler », « Jouer »).

Flow: touch a pawn → chips 1..reste appear (chips whose plan could no longer be completed to exactly 7 are disabled and, on tap, show the disabled hint) → tap a chip: the micro-move joins the plan, the board preview updates (path, captures in transit marked with the × badge at the moment the attacker passes), « Reste » decreases → repeat until « Reste 0 » → « Jouer » confirms once. Undo is LIFO only (order matters): « Retirer le dernier pas » removes the last micro-move and restores the previous preview; « Tout annuler » closes the panel and returns to card selection. Cannot confirm with Reste > 0 (button disabled + hint). Plan rows are not individually removable (avoids order bugs, PITFALLS 2).

### Hand fan (D-07, D-16, D-21)

| Property | Value |
|----------|-------|
| Card size | 72 × 100 compact, 88 × 124 regular (min(viewport w, h) ≥ 600) |
| Count | 1 to 5 |
| Fan geometry | container width `W = viewport − 32`; offset = `min(56, floor((W − cardW) / (n − 1)))` (≥ 54 at n = 5 on a 320px phone, so each visible slice ≥ 44px); rotation = `(i − (n−1)/2) × 4°`; vertical drop = `((i − (n−1)/2)²) × 4px`; transform-origin 50% 160%. n = 1: centred, no rotation. Hit area = the visible slice, extended to 44px minimum width |
| Order | ascending value (As = 1 … Roi = 13), ties by ♠ ♥ ♦ ♣; stable within a deal; played card removed, others re-settle in 200ms |

## Interaction Contract

### Turn flow (D-16, D-19)

1. Own turn: playable cards raised, others dimmed. Nothing is ever played automatically, even with one legal move; that move is only emphasised (D-19).
2. Tap card → playable pawns get halos (As/Roi: first the mode choice if both modes are possible; « Sortir » needs no pawn tap: the preview shows the exit to the diamond 18 directly).
3. Tap pawn → preview (path, captures, ghost) and the description line; for Valet, a second tap on the target.
4. « Jouer » confirms → input is locked until the animation queue is idle (inputs not queued; PITFALLS 12), then the next turn starts.
5. There is no undo after confirmation (REQUIREMENTS out of scope); only before.

### Exchange (D-21, PLAY-05)

At the start of each deal: all cards selectable, prompt « Choisis la carte à passer à {Partenaire}. », button « Passer cette carte ». After confirm the card slides face-down toward the partner's side of the felt; the prompt becomes « En attente de {noms}… » with a hourglass/check per player; bots choose one by one with the bot think delay. When all have chosen, cards cross (300ms), the received card joins the hand with the « Reçue » marker, prompt « Échange fait. … ».

### Dead hand (D-20, RULE-16)

Prompt + « Poser mes cartes » (never automatic for the human). Cards animate (350ms, 60ms stagger) from the hand to the felt in front of the player's seat, face up; then « Tu attends la prochaine donne. » For bots it happens automatically after the think delay, with the bot's posed cards visible on the felt for the rest of the deal.

### Finished player (RULE-17)

When the human's four pawns are home, the partner's pawns carry the playable halos and the prompt « Tes quatre chevaux sont rentrés. Tu joues avec ceux de {Partenaire}. » is shown once at the start of each of that player's turns. Capture previews treat the partner's pawns as the player's own.

### Bot pacing (D-18)

Normal: think delay uniform 700–1300ms (independent of move complexity, PITFALLS 7), then the animation. « Avance rapide » (toggle, persisted, shown whenever bots may play): think 200–300ms, all durations × 0.4 (hoof cadence scales with the animation). The toggle never skips the human's own decisions.

### Keyboard and assistive (baseline, Phase 1)

Every interactive element is a real `<button>`/`role` element with a French accessible name (e.g. « Dame de cœur, jouable », « Cheval bleu, jouable »). Tab order: Réglages → candidate pawns (only when a card is selected) → action buttons → hand cards (arrow keys move between cards, Entrée/Espace selects). `Échap` = deselect / close the open sheet or tray. Focus is visible (amber ring). The aria-live prompt mirrors the visible prompt and bot results. Colour is never the only cue (glyphs, text, halos with shape, × badges). Full WCAG audit remains Phase 5 (APP-05).

### Visibility and background (PITFALLS 12, 18)

On `visibilitychange` to hidden, the animator pauses; on return it applies the end state of all queued events instantly, plays no sounds for skipped events, and shows the latest bot result line.

## Motion Contract (FX-03, FX-04, D-11..D-15)

All motion is `transform`/`opacity` through the Web Animations API on `<g>` wrappers; no per-frame filters; one `hopTimes[]` timetable per move is the single source of truth for both pawn animation and hoof audio.

| Event | Default (normal) | Notes |
|-------|------------------|-------|
| Hop sequence (advance n cells) | total(n) = `400 + 133·(n − 1)` ms, per hop = total / n: 1 cell 400ms, 4 cells 800ms, 13 cells 2000ms (max) | Hop arc height 18% of the cell pitch, 8% squash on landing, last hop settles in 80ms; planner may tune the easing within these bounds (D-11) |
| Backward 4 | Same formula with n = 4 (800ms) after a 120ms volte-face | Head turns toward travel (D-10) |
| Exit from stable (D-15) | One arc bound, 600ms, to the diamond 18 | Neigh at take-off |
| Capture (D-12) | Attacker rears (rotate −14°, rise 14 units) 220ms up + 280ms down on arrival; victim ejected in a parabolic arc to its stable, 700ms, peak 35% of the distance, one 150ms bounce | With the 7, each capture happens as the attacker passes the cell (sequenced mid-move) |
| Valet swap (D-13) | Two crossing arcs, 2 bounds each, 900ms total, simultaneous | Surprised neigh at take-off |
| Enter home (D-14, pawns 1–3) | Hops as normal, final settle 150ms | Sober; joyful short neigh |
| 4th pawn home (D-14) | Rear 500ms + particle burst 700ms (8 small stars/circles, crème and amber, transform+opacity only) | Joyful neigh, light |
| Deal | 20 cards fly from talon to seats, stagger 40ms, 250ms each; own cards flip to face-up | Card sounds |
| Dead hand posed | 350ms per card, 60ms stagger | |
| Card played | Card flies from hand to its felt slot, 300ms | Card sound |
| Win | Winning team's 8 knights hop in place once, 600ms | |
| Prompt cross-fade | 150ms | |
| Sheet in/out | 250ms slide | |

**Fast mode:** all durations × 0.4, bot think 200–300ms. **Reduce motion (FX-06)** replaces the table above with: pawn move = a single 180ms linear slide start → end (no hops, no arcs), capture = victim fades out 150ms then fades in at its stable 150ms, swap = 150ms crossfade, cards = 150ms fade/slide, no pulsing halos (static rings), no particles, no rearing, no banner motion; the game remains fully legible and sounds still play (one hoof clop per move). The setting initialises from `prefers-reduced-motion` and the in-app switch overrides it.

## Audio UX Contract (FX-05, D-22..D-25)

| Event | Sound | Sync |
|-------|-------|------|
| Each hop | Hoof clop | Scheduled on the `AudioContext` clock from `hopTimes[]`, with ±4% pitch and ±1.5 dB jitter |
| Cadence | n ≤ 3: 1 clop per hop (« pas »); 4 ≤ n ≤ 7: 1 clop per hop at the faster tempo (« trot »); n ≥ 8: 2 clops per hop at 0 and 0.5 hop (« galop ») | Follows distance (D-11, FX-04) |
| Exit from stable | Neigh | Take-off of the arc |
| Capture | Attacker snort/neigh at the rear-up, victim whinny at ejection | Rear-up / ejection start |
| Enter home | Joyful short neigh; the 4th pawn: longer joyful neigh | Final settle / rear-up |
| Valet swap | Short surprised neigh | Take-off |
| Deal / card played / exchange | Card sounds (deal riffle, card down, card slide) | With the matching animation |
| Ambiance | Light countryside/stable loop, 1.5s fade-in after unlock, paused when the page is hidden | Own volume (default 30%) and own switch |

Rules: the `AudioContext` is created and resumed inside the « Jouer la partie » tap and retried on any later gesture while `state !== 'running'`; formats AAC `.m4a` primary (+ `.mp3` fallback), decoded once on first unlock; polyphony capped (voice pool, steal oldest); nothing in the game loop ever awaits audio; the game is fully playable muted. Recorded files are CC0 where found; otherwise sounds are generated by code (Web Audio synthesis); every file has a row in `assets/audio/LICENSES.md`, mirrored on the « Crédits et licences » screen.
