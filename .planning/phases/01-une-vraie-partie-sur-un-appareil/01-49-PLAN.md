# Phase 1 Plan 49: Le son de l'iPhone en mode silencieux

## This Plan's Slice (gap closure, UAT test 23, gap G-01-23)

Romain, recette 3 du 2026-10-15 : « Les sons ne fonctionnent pas sur iphone en mode silencieux (pas volume au minimum, mais silencieux, pas de sonnerie) ».

Why it fails: since 01-01, unlock() sets `navigator.audioSession.type = "playback"`, but only after it has created the AudioContext, and it is the only measure. On Romain's iPhone the ringer switch still mutes Web Audio: either the type arrives too late or his Safari ignores it.

Planner's reading, « à confirmer par Romain » (01-CONTEXT.md, « Recette 3 »):
- set the session type first;
- on an iPhone or iPad, also play a silent looping <audio> element from the same gesture. HTML media switches the page to the playback category, which the ringer switch does not mute.
- Known cost: like any app that plays in silent mode, the game interrupts another app's music while it is on screen.

<objective>
Make the game audible on an iPhone in silent mode, inside the existing first-gesture unlock, with the help texts updated and browser tests for what can be tested off-device.

Purpose: success criterion 5 (« y compris sur iPhone ») on Romain's own phone.
Output: keepAlive.ts and its test, unlock order fixed, keep-alive wiring, copy, audio.spec cases, UI-SPEC rows.
</objective>
